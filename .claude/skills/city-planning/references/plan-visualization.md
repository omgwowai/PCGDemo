# 规划图可视化（Phase 2）

产出一张自包含 SVG 的 HTML 页面，用 Artifact 工具发布给用户确认。
发布前先加载 `artifact-design` skill（宿主要求）。修改循环时用同一 file_path 重新发布即可原地更新。

## 页面结构

1. **标题 + 一句话概要**（"~5km² 单中心现代都市，方格路网"）
2. **SVG 规划图**（主体，见下）
3. **关键数字表**：占地、街区尺寸、各分区面积与比例、建筑量级预估、配套清单
4. **待确认问题列表**：把你拿不准的点列出来（"医院放东北角还是中心？"），引导用户逐条回复

## SVG 绘制要点

坐标系：SVG 的 y 向下，UE 的 +Y 向北时要翻转；按 1px = N 米固定比例，图上标注比例尺。

图层顺序（从底到顶）：
1. 地块底色（浅灰）
2. 分区色块：半透明 rect/polygon，颜色语义与 debug 点保持一致——
   商业=橙 `#e8842c`、住宅=红 `#c94a3d`、绿地/公园=绿 `#4a9e4a`、
   公共设施=黄 `#e8d44a`、学校=紫 `#9b4ae8`、医院=青 `#4ad4e8`、工业=灰 `#8a8a8a`
3. 路网：白色粗线（主干道 6px、次干道 3px），方格网直接两组平行线
4. 配套图标：圆点 + 单字母标注（S=学校 H=医院 P=公园 B=公交），配图例
5. 中心点/地标：星形标记

## 生成方式

数据驱动：先把访谈结果整理成分区矩形/多边形列表（内存中的 plan 草稿），再用一段
Python 循环拼 SVG 字符串写入 HTML 文件——不要手写几百行坐标。
这样 Phase 3 的 city_plan.json 和这张图天然同源，不会画一套生成另一套。

修改循环中用户说"商业区往南挪"这类话时：改 plan 草稿 → 重新拼 SVG → 重新发布，
确保确认过的图和最终 JSON 一致。
